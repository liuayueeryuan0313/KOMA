# 学校同步与手动课表合并（未发布）

学校快照、课次身份记录和手动改动分别存储，按用户、课表类型及学期隔离。网页、教学订阅、实验订阅和聚合订阅读取同一份合并结果；发布学校数据、保存修改或处理冲突都在数据库事务中生成有效课表。

## 合并规则

- 手动新建的安排始终保留，不被学校同步覆盖。
- 修改学校课程只保存实际改动的字段；其余字段采用学校最新值。例如仅修改教室，学校更新教师后，新教师仍会显示。
- 手动调整周次、星期或节次时，将这组时间字段一起保留，避免混合两个不同的排课时间。
- 学校同时修改被手动覆盖的字段时，保留手动值并提示待核对。
- 学校取消课程，或同步后无法唯一匹配原课程时，保留手动安排并标记待核对。
- 手动课程与其他课程撞时间时保留双方并标记时间重叠。
- 原有的整学期空响应保护仍然生效，学校整份课表突然变空不会直接删除最近成功版本。

## 两个关键点

**稳定课次身份**：优先使用源数据明确提供的 `sourceOccurrenceId`（需是可靠的逐次排课编号）。没有可靠编号时，以课程代码、原始日期、节次及教学班匹配；调课后只在剩余候选唯一时跟踪同课程同周或跨周移动。名称、教室或教师变化不改变课次身份，不仅凭课程名称匹配。不假定实验 `row_id` 或教务 `kch_id` 是可靠逐次排课编号。当前适配器没有提供可靠编号时自动使用保守匹配。

**恢复学校安排**：修改后的学校课程在编辑弹窗中显示学校最新安排和自己的安排。点击“恢复学校安排”并确认，可撤销本次课的全部手动覆盖；学校已取消的课次会从合并课表移除。点击“保留我的修改”确认当前冲突后提示消失，学校再次变更时会重新提示。提交旧版本表单或处理旧版本比较结果会被拒绝，避免覆盖刚更新的数据。

修改过的课次与手动新建课程使用独立、稳定的 ICS UID。恢复后重新采用学校安排；课程身份记录持续保留。其余课程仍可组成周重复事件。教师、名称、项目或具体时间不同的课次会分组生成，避免将不同周次错误合成同一内容。

## 数据兼容

旧缓存会迁移到分层存储。最初试验版直接覆盖过学校原始行，无法凭空还原被覆盖的内容，因此这些旧手动行会作为独立手动课程保留；从本版开始修改的学校课程具备完整恢复能力。迁移后重复启动、重复同步不会反复导入这些行。

同一用户切换学期时，手动改动按学期保留并隔离；更换学号或学校连接参数仍遵循原有清除课表、凭据和更换订阅链接的规则。

## 验证

55 项 Python、15 项 Node 测试通过，覆盖重复同步、字段覆盖、唯一调课匹配、不明确匹配、稳定源编号、学校取消、确认保留、恢复、旧数据迁移、过期提交、跨用户和跨学期隔离。浏览器使用虚构课程核验了冲突比较与恢复学校最新教室。

仅修改本机源码，未构建镜像、提交、推送或部署。
